# 自主开口：它什么时候说话

> 方案稿（2026-11-22）。只回答一个问题：**它自己决定什么时候开口，怎么决定、怎么验、怎么收手。**
> 投递管道、网关、QQ 都在本文之外，本文只管"该不该说"和"说完怎么送出去"。

## 0 一句话

现在它只有判断、没有时机：判断在 `src/mind/gate.mjs` 里，时机在用户手上。
这份方案把"什么时候开口"从一个开关，改成一个**能被检验的分数**。

## 1 现在为什么说不了

三个缺口，缺一个都说不成话。

**没有叫醒。** 没有任何东西会在用户不说话的时候让它算一次。CLI 只在人去敲命令时才跑。

**算了没用。** `context cue` 能判"可以说"，但判决只回到终端。会话里没有它的嘴，DSH 侧只有 pre-step 注入——那是"被想起"，不是"开口"。

**判断太粗。** 现在的 reasons 只有"有 1 条未巩固""到点日程"这类，全是事件类别，没有轻重。
所以它就算开了口，也只能说出"有 1 条没巩固"这种话——像日志，不像人。

这份方案主要修第三件，顺带把前两件的接口定下来。

## 2 判断换形状：从二选一到打分

gate 现在问的是"说还是不说"。改成问两件事：**这件事值几分，今天的门槛是多少。**

一个"想说的事"（candidate）先算出四个特征：

- **悬念 s** — 有没有没合上的口子，权重最高。
  用户问过而我没答 0.9 / 我答应要做没做 0.8 / 日程到点 0.7 / 群里有话头我接得上 0.6 / 只是一条记录 0.1
- **新近 n** — `exp(-age/halfLife)`，halfLife 默认 3 小时。
  只作用于"事件类"（刚发生的事、群消息）；"债务类"（答应的事、悬着的问题）用固定分，不随时间烂掉——三天前答应的事,今天仍然是欠的。
- **相关 r** — 跟手上这件事、跟最近 20 条消息有没有交集。第一版用关键词重合，够用就行。
- **干扰税 c** — 刚说过 +0.3 / 深夜 +0.5 / 对方正在连着干活 +0.2 / 上次说了没回应 +0.4。

```
score = 1.0·s + 0.5·s·n + 0.6·r − c
```

中间那项是乘的，故意的：没有悬念又旧的事，怎么算都没劲；悬着的事哪怕旧，也还压着一半分。

门槛不是常数，跟着它自己最近的表现浮：

- 基线 0.55
- 最近 24 小时说过 k 次：`T = 0.55 × (1 + 0.2·k)`，上限 1.2
- 静默时段：`×1.8`
- 说出口之后 30 分钟内不再说（现有的 minGap 继续兜底）

**`score > T` 只拿到"可以说"的资格**，说不说还要再掷一次骰子（见 §2.5）。这两步是整份方案的核心，
也是唯一要被单测钉住的东西。

## 2.5 掷骰子：从 QQ 机器人身上借的那一手

两个现成实现（2026-11-22 查）：

- [CharlieNALAN/QQ-AI-Chatbot](https://github.com/CharlieNALAN/QQ-AI-Chatbot)：**未 @ 的普通消息有 5% 概率自动回复**，
  内容限制 20 字内，可按群用 `[修改概率 10]` 调，设 0 即关闭；15 分钟无活动清空上下文。
- [ikechan8370/chatgpt-plugin](https://github.com/ikechan8370/chatgpt-plugin)：伪人模式（BYM）= **概率触发 + 关键词命中
  + 预设覆盖 + 限时撤回**，并把若干条群聊记录注入上下文。

它们解决的是频率，不是判断：5% 是对**每条消息**掷一次骰，消息一多就变成每百条五次乱接话。
但它们有一点东西我们缺——**确定性判决会显得机械**。阈值一过就必说，久了就是闹钟；不到就永远哑，
又像死物。人不是这样，人是"大概想说，今天真没忍住"。

所以第二步接上一层概率：

    p = clamp((score − T) / (上限 − T), 0, 1) × min(1, 剩余今日额度 / 3)
    rand() < p 才真说

比门槛高一点点，多半还是忍着；高出很多，才多半说。额度用完，p 归零——这条比固定百分比厚道，
因为它自带"话越多越省着说"的性质。

再借三条工程细节，都是它们踩过的坑：

- **同一话头只掷一次**：一条消息/一件事只参与一次抽签，不许反复掷到为止。
- **连着被无视就自适应闭嘴**：说了没回应累计两次，冷却时间翻倍（这比固定冷却像人）。
- **每个出口单独配**：群、私聊、当前会话各自有概率与冷却，不共用一份。
- **可调可关**：暴露 `speak.probability` / `speak.daily`，0 即完全静音——它们的 `[修改概率 0]` 是好设计。

## 3 窗口：有分数还得有场合

分数高而没窗口，等于说了没人听。窗口只有三种：

- **一对一会话** — 用户一轮说完（turn 结束）时；以及定时踢醒时（但那句要等用户在场才投）。
- **QQ 群** — 群里有人刚说话。群的好处是窗口天然密集，问题从"什么时候说"降级成"这条接不接"。
- **无窗口** — 分数再高也不说，转成"欠着"，下个窗口优先。

两种场合的权重不一样，群聊里 **r（相关）** 的权重 надо比会话高：接不上就别插嘴；被点名直接置顶。

## 4 说什么：只出口提示，不出口台词

这里撞了本仓库自己的一条禁令——AGENTS 第八条「把语义判断塞进脚本（生成台词、决定该说什么）」。
所以能出口的只有**指认**，不是台词：

    「该说了」理由是：e-20261121-03 你问过、我没答，悬了 1 天

会话里的模型看到这句，用自己的话说出来。agent-man 只负责"哪件事、为什么现在"，不负责措辞。

这也解释了"独立"到哪一层为止：**判断独立**（它自己决定说不说，不靠宿主），**措辞不独立**
（它不调模型，这是边界的第一条）。要它连话都自己说，得先改那条边界——那是另一个决定，
不是这一版的顺手事。

禁止的样子写在这儿，将来谁来投递都照这个判：能出口的句子必须是"指出某件具体的事 + 为什么是现在"；
只报"有 N 条未巩固"、或者"在吗/打扰一下"这类没有任何所指的，都不合格。

## 5 投递链：三件东西，各干一件

1. **`agent-man speak`** — 一次性进程。读处境、算分、过门槛；该说就写信箱，一行 JSON 带 `expires`（默认 45 分钟）。
2. **宿主插件** — 每轮结束读一次信箱，没过期的用 `followup` 投一句进会话。零定时器、零轮询。
3. **账本** — 每次判都记一行：四个特征、score、T、说没说、卡在哪。判"不说"也记。

**过期即丢。** 凌晨想说的话十点才送到，那句话就不该说了。

## 6 降级与开关

- 总开关 `AGENT_MAN_SPEAK=off`：进程都不跑，彻底安静。
- 观察模式（默认）：只记"本想说"，不投递。先跑一周看账本。
- 硬顶：每天最多 3 次，不受分数影响。

## 7 怎么验

第一周拿账本手标 50 条（该说 / 不该说），然后看它真说出口的那些：

- 20 次里用户认可 ≥ 14 次
- 误报（说了但没用）≤ 3 次
- 漏报不计（宁可少说）

不达标先调门槛，**不调模型**。模型只在 P4 之后考虑，而且只接管 r 和 s 的一部分。

## 8 分阶段

| 阶段 | 产出 | 验收 |
|---|---|---|
| P0 | `src/mind/judge.mjs` 纯函数（分数 + 概率）+ 单测 | `npm test` 全绿，分数与 p 的分布合理（同一件事掷 100 次，结果符合 p） |
| P1 | `agent-man speak` + 信箱 + expires | dry-run 默认，账本可读 |
| P2 | DSH 插件取信投递 | 会话里真出现一句它自己说的话 |
| P3 | Windows 计划任务 | 用户不说话时也被叫醒过 |
| P4 | 一周手标校准 | 第 7 节指标达标 |

## 9 不做

- 不做常驻、不做轮询（沿 decisions 第 22 节）。
- 这一版不训模型。训练成果留给"接话质量"，时机先交给规则。
- 不生成台词（AGENTS 第八条）。它出口的是指认 + 理由，措辞归会话里的模型。
- 不改宿主内部：只走 CLI 和信箱，插件永远是可拆的。
- 不管"请求要不要发"——那是网关的事，另一件。

## 10 代价

- 规则打分必然偶尔说出莫名其妙的话。缓解是观察模式 + 每天 3 次硬顶 + 过期即丢。
- 信箱 + 插件是两个部件，插件没跑时它等于没嘴。这是明知换来的：不绑宿主。
- 措辞仍借宿主的模型，所以脱离任何宿主时，它最多把提示打在终端上，说不出"一句人话"。真要自己能说，就得先改"不调用模型"那条边界。
- 关键词相关性很粗，群聊里会误判话题。P4 再换语义匹配。
