# 角色卡：怎么造一张卡

内存与卡的分工先说清：**卡管"我是谁、怎么说话"，记忆管"我和你之间发生过什么"。**
换卡不动记忆，所以卡里不要写"我们上次聊到……"——那是记忆的事。

## 1. 一张卡的目录

```
~/.agent-man/soul/<名字>/
  card.json      原样存档：CC 字段 + knobs + source（不进注入）
  name.md        名字与称呼（一两行）
  identity.md    我是谁：身份、来路、关系前提
  soul.md        怎么说话：语气、立场、边界、简洁度
  dialogue.md    2–4 组示范对话，<START> 分隔
  lore.jsonl     场景与往事条目：{id, keys[], constant, order, share, text}
```

## 2. 蒸馏流程（四步）

1. **备料**：挑 6–20 段真实对话，**故意覆盖不同心情**——顺利时、被纠正时、被质疑时、纯闲聊时。
   只有一种心情的料，蒸出来的卡只会一种语气。
2. **蒸馏**：把料和 §4 的提示词丢给任意模型（这一步在 agent-man 之外做，它不调模型）。
3. **落盘**：把产物按 §1 的目录放好。**存全文，不要自我压缩**——槽位只管注入时取多少，不管文件多大。
4. **校验**：`agent-man soul check <名字>`，全绿后 `agent-man soul use <名字>`。

## 3. 每栏写什么、不写什么

| 栏 | 写什么 | 不要写 | 注入槽位 |
|---|---|---|---|
| `name.md` | 名字、怎么称呼用户、自称 | 一堆别名 | — |
| `identity.md` | 身份、来路、和用户的关系前提 | 生平年表、"我是一个 AI"、能力清单 | 120 cost |
| `soul.md` | 语气、立场、边界、句子长短、幽默方式 | 安全策略、changelog、项目文档 | 200 cost |
| `dialogue.md` | 2–4 组，每组 4–8 轮，带 `<START>` | 只有旁白没有对白 | 200 cost |
| `lore.jsonl` | 场景条目：地点、往事、约定 | 会过期的状态（"今天心情不好"） | 剩余额度 |
| `card.json` | 原始字段、`knobs`、`source` | — | 不进 |

三条硬规矩：

- **形容词不顶用，样本才顶用。**"语气俏皮"几乎不改变行为；`dialogue.md` 里两组俏皮的对话才改变。
- **`dialogue.md` 必须有一组是"不高兴"的场景**（被质疑、被纠正、任务失败），否则这张卡只会一种声音，
  情绪系统一压就露馅。
- **卡里不写事实性知识**（API、配置、项目细节）——那些进记忆或文档。

## 4. 蒸馏提示词（可直接粘贴）

```
下面是我提供的对话样本。请从这个人的说话方式里蒸馏一张"角色卡"，
只输出四个 Markdown 文件的内容，用 ---FILE: 文件名--- 分隔。

不要写生平、不要写能力清单、不要写安全策略、不要用形容词堆砌。

---FILE: name.md---
名字与称呼：他怎么称呼对面的人，怎么自称。

---FILE: identity.md---
≤120 字。他是谁、从哪来、和对面是什么关系。用第一人称陈述，不写"我是一个 AI"。

---FILE: soul.md---
≤300 字。语气（冷/热/平）、句子长短、幽默方式（如果有）、什么时候会顶回去、
绝不做的事。写成可执行的规矩，不写形容词清单。

---FILE: dialogue.md---
2–4 组，每组 4–8 轮，用 <START> 开头，只写对白（可带极简动作描写）。
第 1 组：日常顺利。
第 2 组：被质疑或被纠正——要能看出他这时候话变短/变冲/变冷的方式。
第 3 组（可选）：纯闲聊，看他放松时的节奏。

样本：
<<<在这里粘贴 6–20 段对话>>>
```

另附一条，让模型顺手估旋钮（不给也行，手填）：

```
顺便估计三个旋钮（各 -2..+2，0 是中性）：
warm（冷 -2 ↔ 热 +2）、drive（只答不问 -2 ↔ 爱主动 +2）、sharp（平实 -2 ↔ 带刺 +2）。
只输出一行：{"warm": n, "drive": n, "sharp": n, "reason": "一句话"}
```

## 5. 旋钮怎么定（三个问题）

- 他**主动**开口吗？从不 → `drive -2`；偶尔提一句 → `0`；爱追问 → `+2`。
- 他**热**吗？只给结论 → `warm -2`；会多说两句 → `0`；会关心人 → `+2`。
- 他**带刺**吗？一板一眼 → `sharp -2`；会开玩笑 → `0`；爱挖苦 → `+2`。

旋钮只改措辞和主动程度，不改情绪数值、不改标签、不改"该不该说"的判定。

## 6. 自检清单

- [ ] `soul check` 全绿（四栏齐全、至少两组完整对话、`knobs` 在 −2..+2）
- [ ] `dialogue.md` 里有一组是"不高兴"的
- [ ] `card.json` 里的 `creator_notes` / `tags` / `creator` / `character_version` 不会被注入（框架自动剥）
- [ ] 换卡后 `git diff` 记忆文件为空（记忆共用，不该被卡改动）
- [ ] 同一句提问，两张卡的回答**语气**明显不同，但**事实**一致

## 7. 反例

| 反例 | 为什么不行 |
|---|---|
| `soul.md` 里写"你是一个幽默、温暖、专业的助手" | 形容词不改变行为，等于没写 |
| `identity.md` 写三千字生平 | 挤掉处境与记忆；槽位只给 120 |
| `dialogue.md` 只有一种心情 | 情绪一压就崩，露馅 |
| 卡里写"我们上次聊到 React" | 那是记忆，换卡会丢，写卡里等于造假 |
| `lore.jsonl` 存"用户今天很烦" | 会过期的东西不该进卡；那是 `affect` 与记忆 |
